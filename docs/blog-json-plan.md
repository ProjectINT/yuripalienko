# Блог на JSON-блоках — план внедрения

**Что делаем:** раздел своих статей, где источник правды — типизированный JSON, такой же, как остальной `content/`. Владелец приносит `.md` и картинки, ассистент собирает из них пост (ru + en), сайт рендерит его собственными компонентами. Markdown-парсера в проекте не появляется вообще.

**Дата плана:** 2026-08-17 · **Заменяет:** [docs/blog-md-plan.md](blog-md-plan.md) (движок remark/unified). Решения владельца оттуда перенесены и остаются в силе. **Основа:** [docs/seo-plan.md](seo-plan.md), [docs/palistor-page-plan.md](palistor-page-plan.md) (двуязычность), [docs/deploy-dockhost.md](deploy-dockhost.md).

---

## 0. Почему JSON, а не markdown

| | MD-план (remark) | JSON-план (этот) |
|---|---|---|
| Зависимости | ~8 пакетов (`unified`, `remark-*`, `rehype-*`, `gray-matter`) | **0** |
| Вход | `.md` кладётся в репозиторий как есть | `.md` — исходный материал, ассистент конвертирует его в JSON |
| Разметка на выходе | HTML-строка → `dangerouslySetInnerHTML` | React-компоненты проекта, каждый блок — свой |
| Типографика | ~60 строк `.article` в `globals.css` поверх чужого HTML | классы Tailwind внутри компонентов, как на остальных страницах |
| Типы | нет: что в файле — то и отрендерится | `PostBlock` в `types/content.ts`, ошибка ловится на `tsc`/сборке |
| Однородность с сайтом | новая ветка контента | ровно та же, что `palistor.json`, `cv.json` |
| Миграция в БД | парсить MD на бэкенде или хранить сырой текст | `blocks` кладётся в `jsonb` как есть |
| Цена | статья публикуется без участия ассистента | **каждая статья проходит шаг конвертации** |
| Гибкость текста | любой markdown работает | работает только то, для чего есть тип блока |

Обмен честный: мы платим шагом «собери пост» и получаем ноль зависимостей, типы, единый визуал и готовую к БД форму. При объёме «несколько статей в месяц» шаг конвертации ничего не стоит — он всё равно происходит, потому что перевод на второй язык обязателен (§6).

## 1. Формат поста

Один файл = один пост в одной локали: `content/posts/{ru,en}/{slug}.json`.

```json
{
  "slug": "rynok-po-i-investicii-v-ai-2022-2026",
  "lang": "ru",
  "date": "2026-08-16",
  "updated": null,
  "draft": false,
  "title": "Рынок ПО и инвестиции в AI, 2022–2026",
  "summary": "Что произошло с бюджетами на разработку за четыре года и куда ушли деньги.",
  "seoTitle": "Рынок ПО и инвестиции в AI 2022–2026 | Palisoft",
  "seoDescription": "Разбор цифр: расходы на разработку, доля AI-бюджетов, что это значит для заказной разработки.",
  "ogAlt": "Статья: рынок ПО и инвестиции в AI, 2022–2026",
  "tags": ["ai", "рынок"],
  "cover": { "src": "/posts/rynok-po-i-investicii-v-ai-2022-2026/cover.webp", "alt": "…", "width": 1600, "height": 900 },
  "blocks": []
}
```

| Поле | Правило |
|---|---|
| `slug` | совпадает с именем файла и **одинаков в обеих локалях** — это и есть связка перевода (§6) |
| `date` | `YYYY-MM-DD`, дата написания. Явное поле вместо mtime: в Docker-сборке mtime — время чекаута |
| `updated` | `null` или дата; идёт в `dateModified` и в `lastModified` sitemap |
| `draft` | `true` — пост не попадает ни в списки, ни в `generateStaticParams`, ни в sitemap |
| `title` / `summary` | заголовок страницы (`PageHeader`) и лид; `summary` же — подзаголовок OG-картинки |
| `seoTitle` / `seoDescription` | отдельные от `title`/`summary`, как на всех страницах сайта |
| `cover` | `null` допустим; ширина/высота обязательны — без них `next/image` даст сдвиг вёрстки |
| `readingMinutes` | **не хранится**, считается из `blocks` в `lib/posts.ts` (иначе протухнет при правке текста) |

## 2. Блоки

Дискриминированный union в `types/content.ts`. Стартовый набор закрывает образец статьи (заголовки, абзацы, таблицы до 5 колонок, списки, линейки, сноски) и добавляет то, что точно понадобится дальше (код, картинки, врезки).

```ts
/** Строка с инлайн-разметкой: **жирный**, *курсив*, `код`, [текст](/палистор|https://…) */
export type RichText = string

export type PostBlock =
  | { type: 'heading'; level: 2 | 3; id: string; text: string }
  | { type: 'text'; text: RichText }
  | { type: 'list'; ordered: boolean; items: RichText[] }
  | { type: 'quote'; text: RichText; author: string | null }
  | { type: 'note'; variant: 'info' | 'warn'; text: RichText }
  | { type: 'code'; lang: string; caption: string; code: string }
  | { type: 'table'; caption: string | null; head: string[]; rows: RichText[][] }
  | { type: 'image'; src: string; alt: string; width: number; height: number; caption: string | null }
  | { type: 'divider' }
```

- `code` структурно совпадает с существующим `PalistorCode` → рендерится готовым [components/ui/CodeBlock.tsx](../components/ui/CodeBlock.tsx) вместе с кнопкой копирования. Тип объявляется как `PostCode = PalistorCode`, а не дублируется.
- `heading.id` пишется в JSON явно (транслит слага) — потом на нём и якоря, и оглавление, и `#`-ссылки из текста; генерировать его из русского текста в рантайме не нужно.
- `table` рендерится в контейнере `overflow-x-auto` — таблицы образца на 320px иначе ломают вёрстку.
- Union расширяется по мере надобности: `embed` (YouTube), `toc`, `gallery`, `steps`. Добавление типа = ветка в `switch` + компонент; старые посты не трогаются.

**Правило:** `switch` по `block.type` в рендерере закрывается `never`-проверкой в `default`. Тогда новый тип в union без ветки в рендерере валит `tsc`, а не прод.

## 3. Инлайн-разметка внутри строки — развилка

Внутри абзаца нужны жирный, код, курсив и ссылки. Два способа:

| | Вариант A: массив спанов | **Вариант B: mini-md в строке** ✅ |
|---|---|---|
| Как выглядит | `[{"t":"text","v":"См. "},{"t":"link","href":"/palistor","v":"palistor"}]` | `"См. [palistor](/palistor)"` |
| Читаемость JSON | плохая, абзац разбухает в 5 раз | как обычный текст |
| Diff перевода | шумный | построчный |
| Код рендера | тривиальный `map` | ~50 строк: один `split` по регулярке на 4 конструкции |
| Риск | нет | мини-парсер, который надо покрыть кейсами |
| В БД | одинаково (`jsonb`) | одинаково |

> **Рекомендация: B.** Ровно четыре конструкции — `**жирный**`, `*курсив*`, `` `код` ``, `[текст](url)`. Рендер — `components/blog/RichText.tsx`, возвращает React-узлы, **без** `dangerouslySetInnerHTML`, поэтому экранирование бесплатно.
>
> Бонус: ссылка `/palistor` отдаётся в существующий [components/ui/SmartLink.tsx](../components/ui/SmartLink.tsx) и сама превращается в `/{lang}/palistor` с префетчем. Это снимает пункт «битые внутренние ссылки» из рисков MD-плана — там его пришлось бы чинить отдельным шагом пайплайна.

## 4. Как посты попадают в код — развилка

| | Вариант A: `node:fs` на сборке | Вариант B: статические импорты + барель |
|---|---|---|
| Как | `lib/posts.ts` читает `content/posts/{lang}/*.json` через `readdir`/`readFile` | `content/posts/index.ts` с `import` на каждый пост |
| Новый пост | просто файл | файл + строка в барель |
| Типы | проверяются рантайм-валидатором на сборке | проверяются `tsc` при импорте |
| Бандл | JSON не едет в бандл, только результат SSG | все посты впекаются в серверный бандл |
| Рантайм (OG-роут) | нужен `COPY content` в Dockerfile (§8) | ничего не нужно |
| На 100 постов | ок | серверный бандл растёт на все посты сразу |

> **Рекомендация: A.** `lib/posts.ts` — единственный модуль, который знает, где лежат посты; ровно эта граница потом подменяется на запрос к БД (§13). Строку в барель я всё равно допишу сам, но при варианте B та же граница размазывается по импортам.
>
> Потеря типизации компенсируется валидатором: `lib/posts.ts` проверяет каждый файл (обязательные поля, известный `type` у блока, размеры у картинок, дата в формате) и на сборке падает с сообщением `[posts] content/posts/ru/foo.json: block[7].type "callout" неизвестен`. ~80 строк, ноль зависимостей, ловит мои ошибки конвертации до деплоя.

Читать `fs` в `generateStaticParams`/SSG-компонентах законно: код выполняется на сборке. `dynamicParams = false` на роуте статьи — чтобы неизвестный слаг уходил в 404, а не пытался рендериться в рантайме.

## 6. Двуязычность — решено: перевод обязателен

Сквозное правило сайта: всё, что видит посетитель, существует в обеих локалях. Для статей владелец подтвердил его отдельно (решение от 2026-08-16).

- `content/posts/ru/{slug}.json` + `content/posts/en/{slug}.json`, **одинаковый слаг = пара переводов** → честный `hreflang` без исключений в `alternatesFor`.
- Непарный слаг: `lib/posts.ts` его отсеивает и печатает `[posts] пропущено: {slug} — нет перевода {lang}`. Сборка не падает, URL не существует ни в одной локали (сработает `[...rest]` → 404).
- `draft: true` — легальный способ держать недоделанную пару в репозитории.

**Что обязано совпадать в паре:** `slug`, `date`, состав и порядок блоков, `src`/`width`/`height` картинок, сам `code` в блоках кода. **Что переводится:** весь текст, `alt`, `caption`, комментарии внутри кода. Это же правило уже действует для `palistor.json` — там оно записано в комментарии к `PalistorCode`.

Проверка структурной идентичности пары — часть валидатора из §4: расхождение в длине `blocks` или в `type` по индексу = предупреждение в лог сборки с именем слага.

## 10. Процесс «MD → пост»

Что происходит при каждой статье:

1. **Владелец** кладёт исходники в `drafts/{slug}/` (папка в `.gitignore` и в `.dockerignore`): `text.md` + картинки в любом формате/размере. Говорит: «собери пост».
2. **Ассистент**: режет текст на блоки → `content/posts/ru/{slug}.json`; переводит → `content/posts/en/{slug}.json` (структурно идентичный, §6); жмёт картинки в webp в `public/posts/{slug}/`, проставляет реальные `width`/`height`; пишет `seoTitle`/`seoDescription`/`ogAlt`/`tags`; показывает, что получилось.
3. **Проверка:** `pnpm build` — валидатор ловит структурные ошибки, `tsc` — ошибки типов, глазами смотрим страницу в dev.
4. **Публикация:** `git push` в `main` → Dockhost пересобирает образ сам → статья в проде через ~3–5 минут (решение Q1: публикация на push, SSG).

Правки после публикации — прямо в JSON (это обычный текстовый файл), исходный `.md` больше не нужен и в репозитории не хранится: **источник правды один — JSON**. Два источника разъедутся на первой же правке опечатки.

Когда процесс устоится, шаг 2 стоит завернуть в скилл `.claude/skills/new-post/` — тогда это одна команда, а не описание задачи каждый раз. Не блокирует старт.

## 11. Порядок работ

1. `types/content.ts`: `Post`, `PostBlock`, `RichText`.
2. `lib/posts.ts`: чтение, валидатор, пары по слагу, сортировка по дате, `readingMinutes`. Проверяется отдельно, без UI.
3. `components/blog/RichText.tsx` + блоки + `PostBody.tsx`.
4. `app/[lang]/articles/[slug]/page.tsx`, `dynamicParams = false`.
5. Индекс `/articles`: свои статьи + блок внешних публикаций; подписи в `articles.json` обеих локалей.
6. Метаданные: `metaFor` с `type: article`, `BlogPosting`, трёхуровневые крошки.
7. `opengraph-image.tsx` + строка `COPY content` в `Dockerfile`.
8. `sitemap.ts`.
9. `lib/highlight.ts`: языки + фолбэк.
10. Пилотный пост: образец `rynok-po-i-investicii-v-ai-2022-2026.md` → пара ru/en. Первая настоящая проверка формата блоков — по нему станет видно, каких типов не хватает.
11. `next.config.ts`: immutable для `/posts/:path*`; `drafts/` в `.gitignore` и `.dockerignore`.

Шаги 1–5 дают работающий блог, 6–9 — SEO, 10–11 — контент и мелочи. Шаг 10 сознательно стоит после кода: набор блоков подтверждается на реальной статье, а не выдумывается заранее.

## 12. Миграция в БД

Форма хранения уже совпадает с будущей таблицей — переезд не потребует переписывать ни рендер, ни типы:

```sql
create table posts (
  slug        text not null,
  lang        text not null,
  date        date not null,
  updated     date,
  draft       boolean not null default false,
  title       text not null,
  summary     text not null,
  seo         jsonb not null,   -- seoTitle, seoDescription, ogAlt
  tags        text[] not null default '{}',
  cover       jsonb,
  blocks      jsonb not null,   -- ровно массив PostBlock из файла
  primary key (slug, lang)
);
```

Меняется **только тело `lib/posts.ts`**: `readdir + readFile + JSON.parse` → запрос. Сигнатуры `getPosts(lang)` / `getPost(lang, slug)` / `getPostSlugs()` остаются, компоненты не трогаются. Отсюда правило на всё время файловой стадии: **страницы и компоненты не импортируют JSON постов напрямую и не знают про `fs`** — только через `lib/posts.ts`.

Триггер переезда — не «много статей» (файлов может быть и триста), а появление второго автора или необходимость публиковать без пуша.

## 13. Риски и грабли

- **Неизвестный язык в блоке кода роняет сборку.** Shiki бросает исключение на незнакомом `lang`. Белый список + тихий фолбэк в простой `<pre>` — обязательны.
- **Ошибка конвертации молча уезжает в прод.** Лечится валидатором (§4): без него опечатка в `"type"` даст пустое место на странице вместо падения сборки.
- **Пара разъезжается по структуре.** Правку внесли в `ru`, забыли в `en` → у переводов разный набор блоков. Ловится сверкой структуры в валидаторе (§6).
- **Нехватка типа блока посреди статьи.** Не костылить `text` с версткой внутри — добавить тип в union. Каждый костыль здесь потом переезжает в БД.
- **Русские названия месяцев.** `Intl.DateTimeFormat('ru')` на `node:24-alpine` — проверять в контейнере, а не только локально.
- **`INDEXING_ENABLED`.** Пока флаг выключен, `sitemap.ts` возвращает пустой массив, а `robotsMeta` ставит `noindex`. Существующее поведение, помнить при проверке.
- **Задвоенный H1.** `title` рисует `PageHeader`; в `blocks` заголовка статьи быть не должно, `heading` — только `level: 2 | 3`. Проверяется валидатором.
- **Размеры картинок «на глаз».** `width`/`height` берутся из файла инструментом, не пишутся руками: расхождение = сдвиг вёрстки при загрузке.

## 14. Чек-лист приёмки

- [ ] Пара `content/posts/{ru,en}/{slug}.json` положена, `pnpm build` — статья доступна в обеих локалях, код не тронут
- [ ] `/ru/articles` и `/en/articles` показывают её первой; блок внешних публикаций на месте
- [ ] Файл без пары: сборка жива, статья не публикуется нигде, в логе предупреждение со слагом
- [ ] Битый JSON (неизвестный `type`, отсутствующее поле, кривая дата): сборка падает с внятным сообщением и именем файла
- [ ] Новый тип в `PostBlock` без ветки в `PostBody` — ошибка `tsc`, а не пустое место на странице
- [ ] `hreflang` в паре ссылаются друг на друга, canonical у каждой страницы — на себя
- [ ] Таблица на 5 колонок скроллится на 320px, вёрстка не разъезжается
- [ ] Ссылка `[текст](/palistor)` в тексте ведёт на `/{lang}/palistor`, внешняя — с `rel` и `↗`
- [ ] Картинки не дают сдвига вёрстки; `/posts/*` отдаётся с immutable-кэшем
- [ ] `<title>`, `description`, canonical, `og:type=article`, `publishedTime` — на месте
- [ ] `/ru/articles/{slug}/opengraph-image` отдаёт PNG 1200×630 **в собранном контейнере**
- [ ] Валидатор schema.org: `BlogPosting` + трёхуровневые крошки без ошибок
- [ ] Статья в `sitemap.xml` (при `ALLOW_INDEXING=true`) с корректной датой
- [ ] Блок кода на неподдерживаемом языке не роняет `pnpm build`
- [ ] Русские месяцы корректны внутри alpine-контейнера
- [ ] `docker build` проходит, размер образа вырос незначительно

| № | Вопрос | Решение |
|---|---|---|

**Решено сменой подхода:**

| № | Вопрос | Решение |
|---|---|---|
| Q3 | Движок markdown? | **Не нужен.** Источник правды — JSON-блоки, markdown остаётся форматом черновика |
| Q6 | Типографика? | **Компоненты на токенах проекта**, без `.article` и без плагина typography |
| Q7 | Дата статьи? | **Поле `date` в JSON**, обязательное |

**Открыто — есть рекомендация, старт не блокирует:**

| № | Вопрос | Рекомендация |
|---|---|---|
| Q10 | Инлайн-разметка в строке? | **mini-md** (`**`, `*`, `` ` ``, `[]()`) + `RichText.tsx`, а не массив спанов (§3) |

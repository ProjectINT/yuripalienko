# Деплой на Dockhost

Dockhost собирает образ сам из подключённого Git-репозитория: находит `Dockerfile`
в корне, запускает пайплайн, публикует образ во внутренний реестр и разворачивает
контейнер. Push в отслеживаемую ветку запускает пересборку автоматически
(обнаружение изменений — до двух минут).

## Что уже готово в репозитории

- `Dockerfile` — трёхстадийная сборка (`deps` → `builder` → `runner`) на `node:24-alpine`,
  pnpm через corepack, на выходе `.next/standalone` + `server.js`.
- `.dockerignore` — из контекста исключены `.next`, `node_modules`, `.git`,
  `assets/screenshots` (26 МБ исходников, в рантайме не нужны).
- `next.config.ts` — `output: "standalone"`.
- Контейнер слушает **3000**, `HOSTNAME=0.0.0.0`, работает от пользователя `node`.
- Размер итогового образа — ~228 МБ.

## Порядок действий в панели

1. **Репозитории Git → Добавить.**
   - URL: `https://github.com/ProjectINT/yuripalienko` (для приватного репозитория
     в разделе «Авторизация» указать имя пользователя и GitHub Personal Access Token
     вместо пароля).
   - Ветка: `main`.
   - Dockerfile: `Dockerfile`, контекст сборки: `.`.
   - Ресурсы: 1 CPU, минимум 512 MiB памяти (сборка Next с three.js прожорливее рантайма;
     после первой сборки лимиты контейнера можно снизить).
   - Первая сборка стартует сразу после подключения.
2. **Контейнеры → контейнер приложения → Редактировать → Порты:** добавить `3000`.
3. **Сетевые сервисы → Домены:** добавить домен (динамический от платформы или свой).
4. **Сетевые сервисы → Маршруты:** маршрут с домена на порт 3000 контейнера.
   Первый маршрут в проекте поднимается 1–2 минуты.

## Переменные окружения

`NEXT_PUBLIC_SITE_URL` и `ALLOW_INDEXING` читаются **на сборке**, а не в рантайме:
их значения впекаются в статический HTML (SSG). Поэтому они заданы как `ARG`
в `Dockerfile` со значениями по умолчанию:

```dockerfile
ARG NEXT_PUBLIC_SITE_URL=https://palisoft.ru
ARG ALLOW_INDEXING=true
```

Менять их надо коммитом в `Dockerfile` с последующей пересборкой пайплайна —
переменные окружения контейнера в панели на них не повлияют. Секретов среди них нет,
хранить в репозитории безопасно.

Переменные, которые появятся позже и будут нужны именно в рантайме (ключи API,
адреса внешних сервисов), задаются в панели: «Контейнеры → Редактировать →
Переменные окружения», либо глобально в «Переменные окружения» проекта
со ссылкой `$MY_VAR` в значении переменной контейнера.

## Проверка образа локально

```bash
docker build -t yuripalienko .
docker run --rm -p 3000:3000 yuripalienko
```

Смоук-тест: `/` отдаёт 307 на `/ru` или `/en` по `Accept-Language`, `/ru` — 200,
`/ru/opengraph-image` — PNG 1200×630, `/_next/image?...` — оптимизированный AVIF/WebP.

## Что учесть

- **IP пользователя.** Трафик идёт через балансировщик платформы, реальный адрес —
  в заголовке `x-real-ip`.
- **Шрифты для OG.** `lib/og.tsx` читает `assets/fonts/*.ttf` с диска относительно
  `cwd`, поэтому `Dockerfile` копирует эту папку в рантайм-образ отдельно
  (`.next/standalone` её не трейсит). Роуты `opengraph-image` динамические —
  без шрифтов они упадут в рантайме.
- **Оптимизация картинок.** `sharp` попадает в standalone-трейс автоматически,
  AVIF/WebP на `node:24-alpine` проверены.
- **Откат.** Если сборка сломала прод: «Репозитории Git → нужный пайплайн → ⋮ →
  Перезапустить» откатывает контейнер на предыдущую версию.
